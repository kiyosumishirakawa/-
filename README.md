## 7. AIレビュー記録

### Q1: 設計の妥当性確認

> 「この基本設計書をもとに Arduino UNO R3 でコードを書きます。ピン競合・ライブラリ競合・状態遷移の抜け・delay() の問題点はありますか？」

**AIの回答（要約）：**

LCD1602、超音波センサー、パッシブブザーで使用するArduinoピンは重複していないため、ピン競合はない。  
LCD1602はLiquidCrystalライブラリを使用し、パッシブブザーはtone()を使用する想定であり、大きなライブラリ競合はない。  
状態遷移については、初期化後に距離測定を行い、距離に応じてSafe、Caution、Dangerへ分岐し、その後再び距離測定に戻る流れになっているため、基本的な抜けはない。  
ただし、ブザー制御にdelay()を多用すると、その間は距離測定やLCD更新が止まるため、millis()を使う設計の方が望ましい。

**対応した内容：**

ピン割り当てに重複がないことを確認した。  
また、距離測定・LCD表示・ブザー制御を並行して行いやすくするため、基本的にはmillis()を使用する方針にした。  
起動時のメッセージ表示など、他の処理を止めても問題ない部分のみdelay()を使用する。

### Q2: チャタリング・delay・ノイズの確認

> 「この設計にチャタリング対策は含まれていますか？delay() を使っている箇所で問題はありますか？アナログセンサーを使う場合、ノイズ対策は必要ですか？」

**AIの回答（要約）：**

今回の基本構成ではボタンを使用しないため、チャタリング対策は不要である。  
delay()を使用すると、その間は距離測定や表示更新が停止するため、ブザー制御には注意が必要である。  
また、超音波センサーはアナログセンサーではないため、アナログノイズ対策は不要だが、測定値が一時的に不安定になる可能性はある。  
そのため、0cm以下や400cm超などの異常値を除外する処理を入れるとよい。

**対応した内容：**

ボタンは使用しないため、チャタリング対策は設計に含めないことにした。  
ブザー制御はmillis()を使う方針にし、距離測定やLCD表示が止まらないようにする。  
また、距離が0cm以下または400cmを超える場合は測定範囲外として扱い、ブザーを鳴らさないようにする。

### Q3: 要件への対応漏れ確認（任意）

> 「要件定義書の必須機能と、この基本設計書のSection 5 を比較して、設計漏れや結合テスト計画の抜けを教えてください。」

**AIの回答（要約）：**

必須機能である距離測定、LCD表示、状態判定、ブザー警告、警告メッセージ表示は、Section 5の対応表でそれぞれソフトウェア設計・ハードウェア設計・結合テストに対応している。  
そのため、大きな設計漏れはない。  
ただし、距離を測定できない場合の異常系テストも入れておくと、より安全な設計になる。

**対応した内容：**

Section 6の結合テスト計画に、距離を測定できない場合の異常系テストを追加した。  
センサーの前に物体を置かない、または測定範囲外に向けた場合に、LCDへ「Out of range」などを表示し、ブザーを鳴らさないことを確認する。
