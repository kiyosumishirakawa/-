## Q1. 開発したタイマーの、一番の特徴は何ですか？

4桁7セグLEDを使って、残り時間を「MM.SS」形式で表示できるようにした点です。
また、ポテンショメータで時間を設定できる機能や、カウントダウン終了時にパッシブブザーでメロディを鳴らす機能も追加しました。
単に9秒から0秒まで数えるだけではなく、表示・入力・音の出力を組み合わせたタイマーとして動作するようにしました。

## Q2. 実装時、印象に残った失敗や詰まり、その解決方法は？

症状：
ポテンショメータで時間を設定する機能を追加した際、最大値付近で設定時間が安定せず、表示が期待通りの最大時間にならないことがありました。

ハード由来 / ソフト由来：
ソフト由来

どう解決した：
最初は配線の問題だと思いましたが、Serial Monitorで analogRead() の値を確認したところ、入力値が常に最大値まで安定して届くわけではないことが分かりました。
そのため、読み取った値をそのまま使うのではなく、複数回読み取って平均を取ることや、map() の範囲を調整することで、設定時間が安定するように修正しました。
この経験から、センサーやポテンショメータの入力値は完全に一定ではなく、ソフト側で補正や安定化を行う必要があると学びました。

## Q3. 今日のテストで見つけた一番意外なバグは？

テストケース：
TC-HW3: 電源電圧の確認

何が起きた：
Arduino の 5V ピンと GND ピンの間の電圧を測定したところ、期待値の 4.8V〜5.2V より低い、約4.47Vが測定されました。
タイマー自体は動作していましたが、電源電圧が想定より低かった点が意外でした。

原因（仮説）：
USB給電の電圧低下、接続している4桁7セグLEDやブザーなどの負荷、またはブレッドボードやジャンパ線による電圧降下が原因として考えられます。
今後は Arduino 本体の5V-GND間と、ブレッドボード上の電源ラインを分けて測定し、どの部分で電圧が下がっているのかを切り分けたいです。

## Q4. AIをどう使いましたか？ 良かった点・反省点は？

使った場面：
4桁7セグLEDの表示方式、ポテンショメータの値の扱い、ブザーのメロディ処理、テスト結果の整理、エラー原因の切り分けで使用しました。

良かった点：
エラーが出た時に、配線・コード・部品のどこを確認すればよいかを順番に整理できた点が良かったです。
特に、症状から原因を仮説立てして確認する流れを作る時に役立ちました。

反省点：
AIに質問する時に、最初から自分の回路構成、現在のコード、実際に起きている症状を十分に整理して伝えられないことがありました。
そのため、回答を確認しながら何度も追加で状況を説明する必要がありました。
今後は、AIを使う前に「何をしたいのか」「今どうなっているのか」「どこまで確認したのか」を自分で整理してから質問するようにしたいです。

5月の演習では、動かない時にどこから確認すればよいか分からず、配線やコードを一つずつ見るだけで時間がかかっていました。

## Q6. 配属後、今週の経験をどう活かせそう？

配属後も、プログラムや機器が期待通りに動かない場面があると思います。
その時に、今回のように症状を整理し、ハード由来かソフト由来かを切り分けて、原因を仮説として考える経験を活かしたいです。
また、修正内容だけでなく、確認した手順や判断理由も記録することで、周囲に分かりやすく報告できるようにしたいです。
