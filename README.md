## 本日の学習内容

本日は、タイマーガジェットのテストケースを確認し、基本テストとハードウェアテストを実施しました。
基本テストでは、ボタン連打、カウントダウン中の再押下、0秒到達後の放置、リセットの連続、電源再投入について確認し、いずれも期待通りに動作することを確認しました。

ハードウェアテストでは、テスターを使用して Arduino の電源電圧、GND導通、ブザー出力ピンの電圧を測定しました。
Arduino の 5V-GND間を測定したところ、期待値の 4.8V〜5.2V より低い約4.47Vが測定されました。原因として、USB給電、接続している部品の負荷、ブレッドボードやジャンパ線による電圧降下が考えられると整理しました。
また、ブザー出力については、停止中は0Vでしたが、動作中は約0.5Vとして測定されました。これは、パッシブブザーを tone() により高速なON/OFF信号で駆動しているため、テスターの直流電圧モードでは一定の5Vとして表示されないことが分かりました。

さらに、reflection_sheet.md を使って、今週開発したタイマーの特徴、実装時の失敗、テストで気づいた点、AIの使い方、5月の組込み開発演習からの成長について振り返りました。
GitHubでは、自分のブランチから main への Pull Request を作成しましたが、他メンバーのファイルでコンフリクトが発生しており、現時点ではまだ main へマージできていない状態であることを確認しました。

## Keep

テストケースの内容を一つずつ確認しながら、実際の動作結果を記録できた点は良かったです。
また、テスターを使って電圧やGND導通を確認することで、ソフトウェアだけでなくハードウェア側からも原因を考えることができました。
特に、ブザー動作中の測定値が期待と違った時に、tone() の出力方式とテスターの測定方法を結びつけて考えられた点は良かったです。

## Problem

電源電圧が期待値より低く測定された原因を、まだ完全には特定できていません。
また、GitHubでPull Requestを作成した後、コンフリクトが発生しており、mainへのマージ作業が完了していません。
今後は、Gitのブランチやマージの流れをより正確に理解し、作業場所や対象ファイルを間違えないようにする必要があると感じました。

## Try

次回は、Arduino本体の5V-GND間とブレッドボード上の電源ラインを分けて測定し、どこで電圧が下がっているのかを切り分けたいです。
また、ソフトウェアテストについても、Serial Monitorの状態遷移ログ、境界値テスト、回帰テスト、意図的な遅延テストを順番に確認していきたいです。
GitHubのコンフリクトについては、どのファイルで競合が起きているのかを確認し、必要であれば講師に相談しながら安全に解決したいです。
